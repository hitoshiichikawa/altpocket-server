# 要件定義: タグなしカードで空の `.tags` div を描画しない

- Issue: [#111 タグなしカードで空の .tags div を描画しないようにする](https://github.com/hitoshiichikawa/altpocket-server/issues/111)
- 作成日: 2026-04-24
- 対象ブランチ: `claude/issue-111-impl--tags-div`

## 1. 概要

アイテム一覧ページ (`templates/items.html`) では、各アイテムカード (`.tile.item-card`) の中で `.tags` div を常に描画している。タグが 0 件のアイテムでも空の `<div class="tags"></div>` が生成され、`static/style.css` の `.tags` に指定された `margin-top: var(--space-2)` により、カード下部に約 8px の余白が不要に確保され、タグあり／なしカード間で縦方向の余白が不揃いになる。

本仕様では、タグが 0 件のアイテムカードで `.tags` コンテナが DOM 上に生成されないようにし、グリッド内のカード間の縦方向余白を視覚的に整える。

## 2. スコープ

### 対象

- `templates/items.html` の `91-95` 行目に存在する `.tags` div の描画条件の追加。

### 対象外

- `templates/item_detail.html` (`41-45` 行目) の `#detail-tag-chips.tags`: タグ編集 UI の一部で、JS (`static/app.js`) によって動的にタグチップが追加・削除される。静的に空であっても JS の追加操作対象となるため、本課題の「空 div を描画しない」対応は**適用しない**（`:empty` も後続 JS の追加で効果が失われる）。
- `templates/quick_add.html` (`32` 行目) の `#quick-add-tags.tags`: 同様に JS により動的にチップを挿入するコンテナであり、対象外。
- `.tags` クラスの CSS 定義そのものの変更（`margin-top` や `padding` の値の調整）。本課題では DOM 出力側で解決する。
- 他ページ (`home.html`, `settings.html`, `register.html`, `layout.html`) では `.tags` は使用されていないことを確認済み。

## 3. 機能要件

### FR-1: タグが空のとき `.tags` div を描画しない

- `templates/items.html` のアイテムカード内で、対象アイテムの `Tags` スライスが空（長さ 0）または nil の場合、`<div class="tags">...</div>` 要素を HTML 出力に含めない。

### FR-2: タグが 1 件以上のとき従来どおり描画する

- `Tags` が 1 件以上存在する場合は、従来と同じく `<div class="tags">` 内に `{{range .Tags}}<span class="tag">{{.Name}}</span>{{end}}` が出力される。

## 4. 非機能要件

### NFR-1: 既存レイアウト互換性

- タグを 1 件以上もつ既存アイテムカードのレイアウト・見た目・余白は現状から変化しないこと。
- タグなしカードでは `.tags` の `margin-top` と `padding` が消え、下部の `.actions.item-actions` が直前の `.meta.item-meta` からの自然な余白で配置されること。

### NFR-2: 既存テスト非破壊

- 既存の Go テスト (`go test ./...`) がすべてパスすること。
- 既存のビルド (`go build`) がエラーなく通ること。

### NFR-3: アクセシビリティ

- 空の `.tags` を出さないことで、スクリーンリーダーに対して無意味な空要素を読み上げさせないこと（セマンティクス改善）。

### NFR-4: パフォーマンス

- テンプレート評価コストは無視できる程度の増加に収まる（`{{if}}` 分岐 1 つの追加のみ）。

## 5. 受入基準 (Acceptance Criteria)

### AC-1: タグ 0 件のカードで `.tags` が描画されない

- **Given** `Tags` が空スライスまたは nil のアイテム
- **When** `/ui/items` ページをレンダリングする
- **Then** 当該カードの HTML 出力に `<div class="tags">` 要素が含まれないこと

### AC-2: タグ 1 件以上のカードで従来どおり描画される

- **Given** `Tags` が 1 件以上のアイテム
- **When** `/ui/items` ページをレンダリングする
- **Then** 当該カードの HTML 出力に `<div class="tags">` が含まれ、タグ数と同数の `<span class="tag">` が内包されること

### AC-3: カード間の縦方向余白が揃う

- **Given** タグありカードとタグなしカードが混在する一覧
- **When** ブラウザで `/ui/items` を目視確認する
- **Then** タグなしカードの下部余白が、タグありカードの `.tags` を除いた下部余白と視覚的に同等であり、グリッド内で高さの不自然なばらつきが発生しないこと

### AC-4: 既存のタグリンク・タグ表示が機能する

- **Given** タグに日本語・記号を含む `Name` を持つアイテム
- **When** 一覧を描画する
- **Then** タグ名がエスケープされた上で正しく表示されること（従来の Go `html/template` のエスケープ挙動を維持）

## 6. 実装方針の推奨

### 案 A: テンプレート側で `{{if .Tags}}` 分岐を追加する（推奨）

```go-html-template
{{if .Tags}}
  <div class="tags">
    {{range .Tags}}
      <span class="tag">{{.Name}}</span>
    {{end}}
  </div>
{{end}}
```

- **メリット**
  - DOM 自体が生成されないため、セマンティクス・アクセシビリティの観点で最も明快。
  - スクリーンリーダーに空要素が読み上げられない。
  - 将来 JS で `.tags` に何か挿入する仕様変更が入っても、条件分岐を外すだけで対応可能（振る舞いが明確）。
  - CSS への依存がなく、テンプレート出力のユニットテストで検証しやすい。
- **デメリット**
  - テンプレートが 2 行増える（軽微）。

### 案 B: CSS で `.tags:empty { display: none; }` を追加する

- **メリット**
  - テンプレート変更不要、1 行の CSS 追加のみ。
- **デメリット**
  - DOM 上には空要素が残るため、スクリーンリーダーが無視する保証は弱い。
  - `:empty` は子要素だけでなく**ホワイトスペースやコメントがあっても効かなくなる**ため、テンプレート改行や将来の JS 挿入で壊れやすい。
  - 別箇所の `.tags`（`item_detail.html` / `quick_add.html`）は JS で動的にチップを追加する前は空だが、ロード直後に非表示になると一瞬のフリッカーや初期表示不具合の原因となるため、グローバルな CSS 適用は副作用リスクが高い。

### 結論

**案 A（テンプレート側 `{{if .Tags}}`）を採用する**。DOM を出さない方がセマンティクス・アクセシビリティ・副作用回避の観点で優れ、他ページの `.tags`（編集用動的コンテナ）に影響を与えない。

## 7. テスト観点

### 7.1 自動テスト

- `templates/items.html` を描画する Go の `html/template` ユニットテストがある場合はそこに、無い場合は新規に以下を追加する:
  - **T-1**: タグ 0 件のアイテムを含むデータで描画し、出力 HTML に `class="tags"` が含まれないことを assert する。
  - **T-2**: タグ複数件のアイテムを含むデータで描画し、`<div class="tags">` と `<span class="tag">` がタグ数ぶん含まれることを assert する。
  - **T-3**: タグ 0 件とタグありが混在するデータで、ありカードのみ `.tags` が出現することを assert する。

### 7.2 目視確認

- `/ui/items` を開き、タグありカード／タグなしカードが混在する状態でカード間余白が揃っていることを確認する。
- デベロッパーツールで DOM を確認し、タグなしカードに `.tags` 要素が**無い**ことを確認する。
- ライト／ダークテーマ両方で見た目が崩れないことを確認する（`static/theme.css` の影響範囲外と想定）。

### 7.3 回帰確認

- `go test ./...` が全件成功すること。
- `go build ./...` がエラーなく通ること。

## 8. 確認事項 (Open Questions)

- **OQ-1: CSS ファイルパスの差異**  
  Issue 本文に `static/css/style.css` と記載があるが、実体は `static/style.css`（`static/css/` ディレクトリは存在しない）。Issue 側の記載誤りとして本要件では `static/style.css` を正とする。
- **OQ-2: 他ページの `.tags` 空描画**  
  `templates/item_detail.html` および `templates/quick_add.html` にも `.tags` クラスを持つコンテナが存在するが、これらは JS によって動的にタグチップが追加される編集 UI のため、空でも要素自体は残す必要がある。本 Issue の対象外とし、将来的に余白の見た目を整える必要があるなら別 Issue として扱う。
- **OQ-3: テストインフラ**  
  現状 `templates/items.html` 出力を対象にしたユニットテストは確認できていない（`internal/mcpserver/server_test.go` 以外にテンプレート描画テストが無い可能性あり）。追加する場合は items ハンドラまたはテンプレートレンダラのテストとして最小限に留める方針とする。要望があればテスト追加は別タスクで段階的に進めることも可。
