# Requirements Document

## Introduction

カード一覧のアイテムに付与されているタグは、現状ラベル的な見た目で固定表示されており、
クリックできることが視覚的に伝わらず、実際にクリックしても何も起きない。タグで絞り込むには
サイドバーのチェックボックスまで移動する必要があり、動線が遠い。

本要件は、カード上のタグに「ホバー時の視覚フィードバック」「クリックでの絞り込みトグル」
「キーボード操作対応」を付与し、既存のタグ絞り込み URL クエリ形式（`?tag=<正規化名>` 複数指定可）
と共有・ブックマーク互換を保ったまま、絞り込み動線を短縮することを目的とする。サイドバーの
チェックボックスによる既存の絞り込み操作は維持され、本要件はそれと並列の入口を追加する。

## Requirements

### Requirement 1: タグ要素の視覚的なクリック可能性

**Objective:** As a 一覧画面の閲覧ユーザー, I want カード上のタグがクリック可能であることを見た目で識別できる, so that サイドバーまで移動せずに絞り込み入口を見つけられる

#### Acceptance Criteria

1. While マウスポインタがカード上のタグ要素の上にある間, the Items UI shall ポインタ形状（pointer cursor）を表示する
2. When マウスポインタがカード上のタグ要素に乗ったとき, the Items UI shall 平常時と区別可能な視覚フィードバック（背景・前景・下線等いずれかの状態変化）を表示する
3. When タグ要素がキーボードフォーカスを受けたとき, the Items UI shall ホバー時と同等以上に判別可能なフォーカス表示を表示する
4. While 当該タグが現在の絞り込み条件に含まれている間, the Items UI shall そのタグを「選択中」と判別できる視覚状態で表示する

### Requirement 2: タグクリックによる絞り込みトグル

**Objective:** As a 一覧画面の閲覧ユーザー, I want カード上のタグをクリックして絞り込みを切り替えられる, so that サイドバーを開かずに 1 クリックで該当タグの記事だけに絞り込める

#### Acceptance Criteria

1. When ユーザーが絞り込みに含まれていないタグをクリックしたとき, the Items UI shall そのタグを絞り込み条件に追加して絞り込み結果を表示する
2. When ユーザーが既に絞り込みに含まれているタグをクリックしたとき, the Items UI shall そのタグを絞り込み条件から除外して絞り込み結果を表示する
3. When タグクリックにより絞り込み条件が変化したとき, the Items UI shall サイドバーの同名タグチェックボックスの ON/OFF 状態を新しい絞り込み条件と一致するように更新する
4. When タグクリック由来の絞り込みが反映されたとき, the Items UI shall ブラウザの URL を新しい絞り込み条件を反映した形に更新する
5. When タグクリックにより最後に残っていた絞り込みタグが解除されたとき, the Items UI shall タグ絞り込みなしの一覧結果を表示する

### Requirement 3: 既存 URL クエリ形式との互換性

**Objective:** As a 一覧 URL を共有・ブックマークするユーザー, I want タグクリック後の URL を従来形式と同じ意味で扱える, so that 既存リンクや拡張機能の保存リンクが壊れない

#### Acceptance Criteria

1. When タグクリックで絞り込みが追加されたとき, the Items UI shall 既存のタグ絞り込み URL クエリ形式（タグの正規化名をパラメータ値とする方式、複数指定可）に揃った URL を生成する
2. When タグクリックで URL を更新するとき, the Items UI shall タグ絞り込み以外の既存クエリ（検索キーワード・並び順・1 ページ件数・ページ番号など）を保持する
3. When URL のタグクエリが空になったとき, the Items UI shall 該当クエリパラメータを URL から除去する
4. When ユーザーがタグクリック後の URL を直接開いた、あるいはブラウザの戻る/進むで遷移したとき, the Items UI shall その URL の絞り込み条件と一致する一覧およびサイドバー状態を表示する

### Requirement 4: キーボード・アクセシビリティ対応

**Objective:** As a キーボードのみで操作する利用者および支援技術利用者, I want タグでの絞り込みをマウス利用者と同等に行える, so that 入力デバイスに依存せず絞り込みを利用できる

#### Acceptance Criteria

1. While 一覧画面が表示されている間, the Items UI shall カード上の各タグ要素をキーボードフォーカスで到達可能にする
2. When フォーカスを得ているタグ要素上でユーザーがアクティブ化操作を行ったとき, the Items UI shall クリック時と同じ絞り込みトグル挙動を実行する
3. While タグ要素が選択中の絞り込みに含まれている間, the Items UI shall その選択状態を支援技術が判別できる形（押下状態を示すアクセシブルな属性等）で公開する
4. The Items UI shall 各タグ要素に、そのタグの内容と「クリックで絞り込み可能であること」が支援技術から読み取れるアクセシブルな名称を付与する

### Requirement 5: 既存サイドバー絞り込み挙動の保持

**Objective:** As a サイドバーから絞り込みを操作してきた既存ユーザー, I want これまでのサイドバー操作が同じように動く, so that 既存の使い方を変えずに新しい入口だけ追加で使える

#### Acceptance Criteria

1. The Items UI shall サイドバー側のタグチェックボックス操作による絞り込みフローを、本要件導入前と同等に動作させる
2. When サイドバーのチェックボックス操作で絞り込みが変わったとき, the Items UI shall カード上の対応するタグの選択中ビジュアル状態を新しい絞り込み条件と一致するよう更新する
3. The Items UI shall タグクリック由来の絞り込みとサイドバー由来の絞り込みについて、最終的な絞り込み結果が同一の絞り込み条件であれば同一の一覧を表示する

## Non-Functional Requirements

### NFR 1: ユーザー可視のレスポンス品質

1. When ユーザーがカード上のタグをクリックしたとき, the Items UI shall 視覚的な反応（絞り込み中であることの提示または結果差し替え）を 300ms 以内に開始する
2. While 絞り込み結果の取得中である間, the Items UI shall 既に表示中のカード一覧が空に置き換わってちらつく状態にならないようにする

### NFR 2: 後方互換性

1. The Items UI shall JavaScript を無効化したブラウザ環境でも、本要件導入前と同様にカード一覧の閲覧と既存サイドバーフォーム送信による絞り込みを利用できる状態を維持する
2. The Items UI shall 本要件導入前に生成・共有された絞り込み URL を、これまでと同じ絞り込み結果として解釈する

### NFR 3: 視覚的一貫性

1. The Items UI shall カード上のタグのホバー・フォーカス・選択中表示を、既存のアプリ全体のデザイントークン（色・余白・角丸・モーション）に沿った形で提供する

## Out of Scope

- タグの色分け・アイコン化・絵文字付与など、タグ自体の見た目分類
- タグの編集・名称変更・削除・並び替えに関する UI
- アイテム詳細ページ（`/ui/items/{id}`）におけるタグクリック絞り込み（本要件は一覧画面 `/ui/items` のカード上タグに限定）
- 複数タグの一括選択操作（Shift+クリックによる範囲選択等）
- 拡張機能（Chrome Extension）側のタグ操作 UI
- タグ絞り込みの AND/OR 条件切り替え UI（既存仕様の組合せロジックを維持する）

## Open Questions

- (a) タグクリック時に履歴へ「進む/戻る」可能なエントリを残すか（pushState 相当）、それとも履歴を増やさず置換するか（replaceState 相当）。既存の検索クエリ反映（`items_search.js`）は Enter 押下時 pushState / debounce 時 replaceState の使い分けがあるが、タグクリックは Enter のような明示的コミット操作と debounce の中間に位置する。設計判断として Architect に委ねるか、PM 観点で「ユーザーが戻るで前の絞り込みに戻れる」ことを必須とするかを確認したい
- (b) サイドバーで複数タグを選択中の状態で、カード上のタグ（既に選択中ではない別タグ）をクリックした場合、新しいタグを「追加」するか「単独置換」するか。Issue 本文の仮案からは「ON/OFF トグル」のみが明示されており、複数選択中の追加 vs 単独置換の方針が一意でない。既存サイドバーは複数チェック可能なので「追加」が自然だが、要件として明示が必要
- (c) タグ絞り込み結果取得中（NFR 1.2 のロード状態）に、二重クリックや別タグの連続クリックが起きた場合の打ち切り規約。`items_search.js` では AbortController で前段リクエストを破棄する規約があるが、本要件で同等の挙動を必須とするかは Architect 判断に寄せるか、PM 要件として固定するかを確認したい
