# Requirements Document

## Introduction

`/ui/items` 一覧画面では、現在適用中のタグ絞り込みはサイドバー（およびモバイルの
ボトムシート）内のチェックボックスにしか可視化されておらず、メインエリアの一覧結果
だけを見ているユーザーは「いま何で絞り込まれているか」を把握しにくい。フィルタの解除も、
該当チェックボックスまで視線・操作を戻す必要がある。

本要件は、メインエリア上部（検索バーと一覧の間）に「現在のアクティブフィルタ」を
チップ列として可視化し、各チップから 1 クリックで個別解除、および全フィルタの一括解除
ができるようにすることで、絞り込み状況の視認性と解除動線を改善する。

直前に merge 済みの Issue #117（カード上タグのクリック絞り込み）で導入された、
URL クエリ `?tag=<正規化名>`（複数指定可）を正準形式とするフィルタ機構、サイドバーの
タグチェックボックスとカード上タグの双方向同期、`X-Requested-With: ItemsFragment` 経由
の一覧フラグメント差し替えと AbortController 共有レース対策、JS 無効環境での form
submit による従来フローの互換性、これらの既存挙動と矛盾しない形で実装する必要がある。

## Requirements

### Requirement 1: アクティブフィルタチップの可視化

**Objective:** As a 一覧画面の閲覧ユーザー, I want メインエリア上部で現在のフィルタを一目で確認できる, so that サイドバーまで視線を移さずに「いま何で絞り込まれているか」を把握できる

#### Acceptance Criteria

1. While アクティブなタグ絞り込みが 1 件以上ある間, the Items UI shall メインエリア上部（検索バー直下・一覧結果の上）にアクティブフィルタチップ列を表示する
2. While アクティブなタグ絞り込みが 1 件もない間, the Items UI shall アクティブフィルタチップ列を表示しない（領域自体を出さない）
3. The Items UI shall 各チップに対象タグの表示名（正規化前の元の表示名）を表示する
4. The Items UI shall 各チップに、そのフィルタを解除するための操作要素（解除ボタン相当）を含める
5. The Items UI shall アクティブフィルタチップを、サイドバーのタグチェックボックスで `checked` のタグおよび現在 URL の絞り込みクエリと同じ集合で表示する

### Requirement 2: チップによる個別フィルタ解除

**Objective:** As a 一覧画面の閲覧ユーザー, I want チップの解除ボタンを押すだけでそのタグの絞り込みを外せる, so that サイドバーへ視線を戻さず該当フィルタだけを 1 操作で取り除ける

#### Acceptance Criteria

1. When ユーザーがチップの解除操作要素をクリックしたとき, the Items UI shall 当該タグを絞り込み条件から除外する
2. When チップ操作によって絞り込み条件が変化したとき, the Items UI shall 新しい絞り込み条件を反映した一覧結果を表示する
3. When チップ操作によって絞り込み条件が変化したとき, the Items UI shall サイドバーの同名タグチェックボックスを新しい絞り込み条件と一致するよう更新する
4. When チップ操作によって絞り込み条件が変化したとき, the Items UI shall カード上の同名タグ要素の選択中表示を新しい絞り込み条件と一致するよう更新する
5. When チップ操作によって最後の 1 件のアクティブタグが解除されたとき, the Items UI shall タグ絞り込みなしの一覧結果を表示する
6. When チップ操作によって絞り込み条件が変化したとき, the Items UI shall ブラウザの URL を新しい絞り込み条件を反映した形に更新する

### Requirement 3: 「すべてクリア」による一括解除

**Objective:** As a 一覧画面の閲覧ユーザー, I want 「すべてクリア」操作で全タグフィルタを一括解除できる, so that 複数タグで絞り込んだ後に全体一覧へ素早く戻れる

#### Acceptance Criteria

1. While アクティブなタグ絞り込みが 1 件以上ある間, the Items UI shall アクティブフィルタチップ列に「すべてクリア」操作要素を表示する
2. When ユーザーが「すべてクリア」操作要素を起動したとき, the Items UI shall すべてのタグ絞り込みを解除する
3. When 「すべてクリア」操作によって絞り込み条件が変化したとき, the Items UI shall タグ絞り込みなしの一覧結果を表示する
4. When 「すべてクリア」操作によって絞り込み条件が変化したとき, the Items UI shall サイドバーの全タグチェックボックスを未選択状態に更新する
5. When 「すべてクリア」操作によって絞り込み条件が変化したとき, the Items UI shall カード上の全タグ要素の選択中表示を解除する
6. When 「すべてクリア」操作によって絞り込み条件が変化したとき, the Items UI shall ブラウザの URL からタグ絞り込みクエリパラメータを除去する

### Requirement 4: 既存フィルタ機構との状態同期

**Objective:** As a サイドバー操作・カード上タグ・URL 直接入力など複数経路で絞り込みを変えるユーザー, I want どの経路で絞り込みを変えてもアクティブフィルタチップ列が常に最新の状態と一致している, so that 表示状態の不一致による誤認を起こさない

#### Acceptance Criteria

1. When サイドバーまたはボトムシートのチェックボックス操作によって絞り込み条件が変わったとき, the Items UI shall アクティブフィルタチップ列を新しい絞り込み条件と一致するよう更新する
2. When カード上タグのクリックトグルによって絞り込み条件が変わったとき, the Items UI shall アクティブフィルタチップ列を新しい絞り込み条件と一致するよう更新する
3. When 一覧フラグメントが非同期に差し替えられたとき, the Items UI shall アクティブフィルタチップ列を差し替え後の URL クエリと一致する状態に保つ
4. When ユーザーがブラウザの戻る・進む操作で前後の絞り込み状態に遷移したとき, the Items UI shall アクティブフィルタチップ列をその時点の URL クエリと一致する状態に表示する
5. When ユーザーがアクティブフィルタを含む URL を直接開いたとき, the Items UI shall ページ初期表示時点でアクティブフィルタチップ列を URL クエリと一致する状態に表示する

### Requirement 5: 既存 URL クエリ形式との互換性

**Objective:** As a 既存の絞り込み URL を共有・ブックマーク・拡張機能で利用しているユーザー, I want 本機能導入後も既存リンクがこれまでと同じ絞り込み結果として解釈される, so that 既存リンク・拡張機能が壊れない

#### Acceptance Criteria

1. When チップ操作または「すべてクリア」操作で URL を更新するとき, the Items UI shall タグ絞り込みクエリの正準形式（タグ正規化名をパラメータ値とする `tag` パラメータの繰り返し）に揃った URL を生成する
2. When チップ操作または「すべてクリア」操作で URL を更新するとき, the Items UI shall タグ絞り込み以外の既存クエリ（検索キーワード、並び順、1 ページ件数、ページ番号など）を保持する
3. When すべてのアクティブタグが解除されたとき, the Items UI shall URL からタグ絞り込みクエリパラメータを除去する
4. The Items UI shall 本要件導入前に共有された絞り込み URL を、これまでと同じ絞り込み結果として解釈する

### Requirement 6: キーボード・アクセシビリティ対応

**Objective:** As a キーボードのみで操作する利用者および支援技術利用者, I want チップによる解除操作をマウス利用者と同等に行える, so that 入力デバイスに依存せずアクティブフィルタを管理できる

#### Acceptance Criteria

1. While アクティブフィルタチップ列が表示されている間, the Items UI shall 各チップの解除操作要素および「すべてクリア」操作要素をキーボードフォーカスで到達可能にする
2. When キーボードフォーカスを持つチップの解除操作要素でユーザーがアクティブ化操作を行ったとき, the Items UI shall マウスクリック時と同じ個別解除挙動を実行する
3. When キーボードフォーカスを持つ「すべてクリア」操作要素でユーザーがアクティブ化操作を行ったとき, the Items UI shall マウスクリック時と同じ一括解除挙動を実行する
4. The Items UI shall 各チップの解除操作要素に、対象タグ名と「フィルタ解除」の意味が支援技術から読み取れるアクセシブルな名称を付与する
5. The Items UI shall 「すべてクリア」操作要素に、全フィルタ解除の意味が支援技術から読み取れるアクセシブルな名称を付与する

## Non-Functional Requirements

### NFR 1: ユーザー可視のレスポンス品質

1. When ユーザーがチップ解除または「すべてクリア」を起動したとき, the Items UI shall 視覚的な反応（チップ列の更新または一覧の更新開始）を 300ms 以内に開始する
2. While 解除操作後の一覧結果取得中である間, the Items UI shall 既に表示中のカード一覧を空状態で置き換えてちらつかせる挙動を発生させない
3. When 短時間に複数のチップ解除操作が連続して行われたとき, the Items UI shall 最終的に最後の操作後の絞り込み条件と一致する一覧結果およびチップ列を表示する

### NFR 2: 後方互換性

1. The Items UI shall JavaScript を無効化したブラウザ環境でも、本要件導入前と同様に一覧の閲覧およびサイドバーフォーム送信による絞り込みを維持する
2. The Items UI shall 本要件導入前に生成・共有された絞り込み URL を、これまでと同じ絞り込み結果として解釈する
3. The Items UI shall 本要件導入後も、Issue #117 で導入されたカード上タグのクリック絞り込み挙動を変更しない

### NFR 3: 視覚的一貫性

1. The Items UI shall アクティブフィルタチップ列の配色・余白・角丸・モーションを、既存アプリ全体のデザイントークン（カード上タグ・status-pill 等の既存スタイルと整合する形）に沿って提供する
2. The Items UI shall モバイル幅とデスクトップ幅のいずれにおいてもアクティブフィルタチップ列をメインエリア上部の同一位置に表示する

## Out of Scope

- 検索キーワード（`?q=`）自体のチップ表示（Issue 本文の明示的なスコープ外。タグフィルタを先行）
- 並び順（`?sort=`）・1 ページ件数（`?per_page=`）のチップ表示
- アクティブフィルタチップの並び替え機能（Issue 本文の明示的なスコープ外）
- 複数チップの範囲選択や Shift+クリック等の高度な複合操作
- アクティブフィルタの保存・お気に入り・プリセット機能
- アイテム詳細ページ（`/ui/items/{id}`）でのアクティブフィルタ表示（本要件は `/ui/items` に限定）
- 拡張機能（Chrome Extension）側のアクティブフィルタ表示
- タグ絞り込みの AND / OR 切り替え UI（既存仕様の組合せロジックを維持）
- アクティブフィルタチップ列内での新規タグ追加 UI（解除のみを担当）

## Open Questions

- (a) チップ列の表示位置をデスクトップとモバイルで一致させるか、モバイルでは別位置（例: フィルタトグルバーの下、ボトムシート起動ボタンの近傍）に置く方が UX として自然か。Issue 本文は「メインエリア上部」と指定しているのみで、モバイルの具体的な位置は判断を委ねたい
- (b) チップ操作後のブラウザ履歴粒度。Issue #117 のタグクリックは pushState で「戻るで前の絞り込みに戻れる」を採用しているが、本要件の「フィルタ解除」は逆向きの操作であり、pushState で履歴を増やすべきか、replaceState で履歴を増やさず置換するかを確定したい（PM 観点では「戻るで解除前の絞り込みに戻れる」を採用する方が一貫性が高いが、明示確認が必要）
- (c) SSR で初期チップ列をレンダリングするか、JS が DOM 構築時にクライアント側で生成するか。NFR 2.1（JS 無効環境互換性）を満たすには SSR で初期チップを描画する方が安全だが、Issue 本文には「SSR 主導 vs クライアント側生成」の判断を委ねる旨が明示されている。要件として「JS 無効環境でも初期表示時点でアクティブフィルタが画面上に可視化されること」を必須にするかどうかは Architect 判断に寄せるか、PM 要件として固定するかを確認したい
- (d) チップ操作時の一覧結果取得経路を、Issue #117 / #114 と同じ `X-Requested-With: ItemsFragment` フラグメント取得経路で行うか、フルページ遷移にするか。NFR 1.2（ちらつき防止）と Issue #117 既存の AbortController 共有レース対策を踏まえると前者が自然だが、明示確認が望ましい
