# Implementation Plan

- [x] 1. 認証状態と初期画面遷移を安定化する
- [x] 1.1 未認証初期表示をログイン導線のみに固定する
  - Side Panel 起動時に未認証状態を判定し、ログイン画面以外を表示しない。
  - 未認証中は記事一覧取得やタグ候補取得など認証前提の操作を実行しない。
  - 認証後画面へ誤遷移しないことを状態遷移条件で保証する。
  - _Requirements: 1.1, 1.2, 1.5_
- [x] 1.2 サインイン成功/失敗の遷移ルールを統一する
  - サインイン成功時はトークン保存後に閲覧画面へ遷移する。
  - サインイン失敗時は未認証画面を維持し、再試行可能な状態を保つ。
  - 未登録ユーザー、トークン欠損、通信失敗を区別して通知する。
  - _Requirements: 1.3, 1.4_
- [x] 1.3 認証失効時の復帰動作を共通化する
  - 認証エラー受信時の処理を単一フローへ集約する。
  - セッション失効時は未認証画面へ即時復帰し、再ログインを促す。
  - _Requirements: 1.5, 5.3_

- [x] 2. 固定ユーティリティ導線を完成させる
- [x] 2.1 閲覧画面上部に固定ユーティリティ領域を構成する
  - 画面上部に `altpocket` 表示と運用導線領域を常時表示する。
  - ユーティリティ領域を記事一覧のスクロール領域外に配置する。
  - 狭い表示領域でも視認性を維持できるレイアウトに調整する。
  - _Requirements: 2.1, 2.2, 2.5_
- [x] 2.2 `Go to website` 導線を実装する
  - ユーザー操作で Web のアイテム一覧ページを新規タブで開く。
  - 拡張機能内で未提供の運用操作を Web 側に委譲する前提を明示する。
  - _Requirements: 2.3, 5.2_
- [x] 2.3 ログアウトを実装し未認証画面へ戻す
  - ログアウト時にトークン関連のローカル保存値を全破棄する。
  - ログアウト完了後は未認証画面へ遷移し、認証前状態を再初期化する。
  - _Requirements: 2.4_

- [x] 3. 保存セクションと非同期取得連携を実装する
- [x] 3.1 保存セクションの入力体験を整える
  - 保存セクションに `Save current tab`、タグ入力、タグ候補、選択タグ表示を実装する。
  - タグ追加・削除操作を即時反映し、重複タグ入力を防止する。
  - _Requirements: 3.1, 3.2, 3.3_
- [x] 3.2 現在タブ保存の API 連携と成功通知を実装する
  - 現在タブ URL と選択タグを保存 API に送信する。
  - 保存成功時にユーザーへ状態通知し、一覧更新をトリガーする。
  - _Requirements: 3.4_
- [x] 3.3 新規保存時のみ本文 capture を非同期送信する
  - 新規作成された記事に限定して本文抽出と capture 送信を実行する。
  - 本文抽出不可ページでは保存成功を維持しつつ capture を安全にスキップする。
  - _Requirements: 3.5_

- [x] 4. 検索とコンテンツ一覧の表示仕様を完成させる
- [x] 4.1 保存と閲覧を分離するレイアウトを実装する
  - 保存セクション下に視覚的区切りを追加し、検索・一覧領域を分離する。
  - 区切り配下に検索入力と一覧領域を配置する。
  - _Requirements: 4.1, 4.2_
- [x] 4.2 検索条件と並び順の連携を実装する
  - 件名・本文検索用テキスト・タグを対象にした検索条件を API へ連携する。
  - 検索語ありでは relevance、なしでは newest を適用する。
  - _Requirements: 4.3_
- [x] 4.3 一覧行の表示情報を最小構成に固定する
  - 各行に件名、タグ一覧、`Show original` 操作のみを表示する。
  - 本文テキストとステータス表示を一覧から除外する。
  - _Requirements: 4.4, 4.5_

- [x] 5. 責務境界と障害時挙動を明確化する
- [x] 5.1 拡張機能で提供しない操作を明示的に除外する
  - 記事編集、削除、再フェッチ要求を拡張機能の操作面から除外する。
  - 追加操作が必要な場合は Web 導線を利用する一貫運用を維持する。
  - _Requirements: 5.1, 5.2_
- [x] 5.2 認証エラー時の失効処理を一貫化する
  - 一覧取得と保存処理での認証エラーを共通に扱う。
  - 認証失効時はセッション破棄と未認証画面復帰を必ず実行する。
  - _Requirements: 5.3_
- [x] 5.3 権限不足と通信障害の通知挙動を実装する
  - API オリジン権限不足時に対象操作を中断し、原因を識別可能な形で通知する。
  - ネットワーク障害時に再試行可能な通信失敗通知を表示する。
  - _Requirements: 5.4, 5.5_

- [x] 6. 回帰防止テストと統合検証を強化する
- [x] 6.1 (P) 拡張機能の主要ユーザーフロー自動テストを拡張する
  - 認証前後画面遷移、保存、検索、ログアウトの回帰テストを維持する。
  - 一覧取得の通信障害と `Go to website` 導線の検証ケースを追加する。
  - _Requirements: 1.1, 1.3, 2.3, 2.4, 3.4, 4.3, 5.5_
- [x] 6.2 (P) API 契約と検索挙動のバックエンド検証を追加する
  - extension 認証交換、一覧取得、保存、capture の契約整合を検証する。
  - relevance 並び・CORS 許可判定・認証失効ケースの回帰を検証する。
  - _Requirements: 1.3, 3.4, 3.5, 4.3, 5.3, 5.4_
- [x] 6.3 統合テスト実行と不整合解消を完了する
  - 拡張機能テストと Go テストを通しで実行し、失敗を解消する。
  - 依存関係のある修正を統合し、最終的な受け入れ可能状態を確認する。
  - _Requirements: 1.1, 2.4, 3.5, 4.4, 5.5_
