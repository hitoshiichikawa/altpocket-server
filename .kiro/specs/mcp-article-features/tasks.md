# Implementation Plan

- [x] 1. DBマイグレーションとAPIキーストア層の構築
- [x] 1.1 MCP APIキー用のデータベーステーブルを作成する
  - APIキーのハッシュ、プレフィックス、ユーザー紐付け、作成日時を管理するマイグレーションを追加する
  - ハッシュカラムにユニーク制約とインデックスを設定して検索性能を確保する
  - ユーザー削除時のカスケード削除を設定する
  - _Requirements: 7.2, 8.1_

- [x] 1.2 APIキーのCRUDおよび検証用のストアメソッドを実装する
  - APIキーの作成（ハッシュ・プレフィックス保存）、一覧取得、検証（ハッシュ照合→userID返却）、削除の各メソッドを追加する
  - 検証メソッドではハッシュが一致しない場合にエラーを返す
  - 削除時はユーザーIDとキーIDの両方で照合し、他ユーザーのキーを削除できないようにする
  - _Requirements: 7.2, 7.3, 8.1, 8.3, 8.4_

- [x] 1.3 (P) 過去N時間以内に作成された記事を取得するストアメソッドを実装する
  - 指定日時以降に作成された記事をタグ付きで取得し、作成日時の新しい順で返す
  - 結果が0件の場合は空スライスを返す
  - _Requirements: 6.1, 6.2_

- [x] 2. MCP Server基盤とツール/リソースハンドラーの実装
- [x] 2.1 MCP SDKを導入し、ツールとリソースを登録したMCP Serverインスタンスを生成する
  - Go公式MCP SDKの依存を追加する
  - サーバー名・バージョン・対応capabilitiesを設定する
  - 4つのツールと1つのリソースの定義を登録する
  - Streamable HTTP transportのハンドラーを生成して返す関数を用意する
  - _Requirements: 1.1, 1.4, 1.5_

- [x] 2.2 (P) 記事一覧取得ツールのハンドラーを実装する
  - ページネーション（page, per_page）とソート（newest/oldest）パラメータを受け取る
  - デフォルト値の適用とper_pageの上限（50）制限を行う
  - 既存のストア層を呼び出して記事一覧とページネーション情報をJSON形式で返す
  - 結果が0件の場合は空配列とtotal_count: 0を返す
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

- [x] 2.3 (P) 記事検索ツールのハンドラーを実装する
  - キーワード検索（query）とタグ絞り込み（tags）をサポートする
  - queryとtagsの両方が指定された場合はAND結合で検索する
  - queryのみ指定時は関連度順、tagsのみ指定時は新しい順でソートする
  - queryもtagsも未指定の場合はパラメータ不足エラーを返す
  - ページネーションをサポートする
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

- [x] 2.4 (P) 記事詳細取得ツールのハンドラーを実装する
  - 記事IDを受け取り、メタデータ・全文コンテンツ・タグ一覧を含む詳細情報を返す
  - 存在しないIDの場合は「記事が見つかりません」エラーを返す
  - 取得状態がpending/fetchingの場合は全文コンテンツを空として返し、fetch_statusを明示する
  - _Requirements: 4.1, 4.2, 4.3_

- [x] 2.5 (P) タグ一覧取得ツールのハンドラーを実装する
  - 全タグを記事数降順で取得し、名前・正規化名・記事数を返す
  - queryパラメータが指定された場合はタグ名で前方一致フィルタする
  - _Requirements: 5.1, 5.2_

- [x] 2.6 (P) 新着記事リソースのハンドラーを実装する
  - 過去24時間以内に作成された記事一覧をリソースとして返す
  - リソースURIとして`altpocket://recent-articles`、名前として「新着記事（過去24時間）」を公開する
  - 0件の場合でも空配列を含む有効なJSONを返す
  - _Requirements: 6.1, 6.2, 6.3_

- [x] 3. MCP認証ミドルウェアの実装
- [x] 3.1 Bearer Token認証ミドルウェアを実装する
  - Authorizationヘッダーからトークンを抽出し、SHA-256ハッシュを計算してDB照合する
  - 一致するAPIキーが見つかった場合はuserIDをリクエストコンテキストに格納して後続に転送する
  - トークン欠如・不一致の場合は401 Unauthorizedを返す
  - 認証失敗時はWARNログを出力する
  - _Requirements: 7.1, 7.2, 7.3, 7.4, 7.5_

- [x] 4. APIキー管理UIの実装
- [x] 4.1 APIキー生成ハンドラーを実装する
  - crypto/randで32バイトのランダムキーを生成し、hex文字列に変換する
  - SHA-256ハッシュを計算してDBに保存する
  - 平文キーをセッション経由でフラッシュメッセージとして渡し、設定画面にリダイレクトする
  - CSRF保護を既存パターンに従って適用する
  - _Requirements: 8.1, 8.2_

- [x] 4.2 APIキー失効ハンドラーを実装する
  - パスパラメータからキーIDを受け取り、ログイン中ユーザーのキーのみ削除可能にする
  - 削除後は設定画面にリダイレクトする
  - _Requirements: 8.4_

- [x] 4.3 設定画面テンプレートにMCPセクションを追加する
  - 既存の設定画面にMCP API Keysセクションを追加する
  - 既存APIキーの一覧（プレフィックス、作成日時、失効ボタン）を表示する
  - 「Generate New Key」ボタンを配置する
  - 生成直後はフラッシュメッセージで平文キーをコードブロックとして1回表示し、コピーボタンと再表示不可の警告文を添える
  - MCPクライアント設定例（接続URL、Bearerトークン）を表示する
  - _Requirements: 8.2, 8.3, 8.4, 8.5_

- [x] 5. APIサーバーへのMCPエンドポイント統合
- [x] 5.1 既存chiルーターにMCPエンドポイントと認証ミドルウェアをマウントする
  - `/mcp`パスにMCP SDKのHTTPハンドラーをマウントする
  - 認証ミドルウェアをMCPルートに適用する
  - APIキー管理UIのルート（生成・失効）を既存UIルートグループに追加する
  - 設定画面ハンドラーにAPIキー一覧データを渡す
  - _Requirements: 1.2, 1.3_

- [x] 5.2 MCP統合の動作検証テストを実装する
  - 認証ミドルウェアのユニットテスト（有効トークン、無効トークン、ヘッダー欠如）
  - ツールハンドラーの入力バリデーションテスト（デフォルト値、範囲チェック、必須パラメータ）
  - APIキーストアメソッドのテスト（生成、検証、削除、一覧）
  - _Requirements: 1.1, 7.1, 7.4_
