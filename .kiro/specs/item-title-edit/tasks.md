# Implementation Plan

- [x] 1. アイテム部分更新のデータ層を実装する
- [x] 1.1 タイトルとタグをオプションで一括更新できるデータ操作メソッドを新設する
  - トランザクション内で所有権チェック → タイトル更新（指定時のみ） → タグ置換（指定時のみ） → コミットを行う
  - タイトルもタグも未指定の場合でも所有権チェックは実行する
  - アイテム未存在または非所有者の場合はエラーを返す
  - 更新後のタイトルとタグの現在値を返却する
  - タグ置換ロジックは既存のタグ操作処理（DELETE → INSERT → 孤立タグ削除 → SELECT）を移植する
  - _Requirements: 2.1, 2.3_

- [x] 1.2 既存のタグ置換メソッドを新メソッドのラッパーに変更する
  - メソッドのシグネチャと戻り値の型は既存のまま維持する
  - 内部で新メソッドをタイトル未指定で呼び出す形に書き換える
  - 既存のタグ更新ハンドラーからの呼び出しに影響がないことを確認する
  - _Requirements: 2.2_

- [x] 2. アイテム部分更新の API エンドポイントを実装する
- [x] 2.1 PATCH エンドポイントのハンドラー実装とルート登録を行う
  - 認証チェック、レート制限チェック、JSON デコードを既存パターンに従い実装する
  - タイトルが指定されている場合はトリム処理を行い、トリム後空文字なら 400 エラーを返す
  - データ層の新メソッドを呼び出し、エラーに応じて 400 / 404 / 429 / 500 を返す
  - 成功時は更新後のタイトルとタグを JSON レスポンスで返却する
  - items ルートグループに PATCH ルートを登録する
  - _Requirements: 2.1, 2.3, 2.4, 3.2_

- [x] 3. フロントエンドにタイトル編集を統合する
- [x] 3.1 (P) テンプレートにタイトル編集用の入力フィールドを追加する
  - タイトル表示要素の直後に、初期状態で非表示のテキスト入力フィールドを追加する
  - 編集モード時にタイトル表示を隠して入力フィールドを表示する構造にする
  - 既存の Save / Cancel ボタンをタイトルとタグで共有する（新規ボタンは追加しない）
  - _Requirements: 1.1, 1.2_

- [x] 3.2 タグ編集ロジックにタイトルの状態管理と保存処理を統合する
  - 編集開始時にタイトルの元の値を保持し、入力フィールドに現在のタイトルを初期値として設定する
  - キャンセル時にタイトル表示を元の値に復帰する
  - 保存時に PATCH エンドポイントへタイトルとタグを一括送信する
  - 保存前にタイトルの空文字チェック（トリム後）を行い、空なら保存を中止してエラー通知する
  - 保存中は Save ボタンを無効化し二重送信を防止する
  - 保存成功後にタイトル表示とブラウザのページタイトル（`{新タイトル} | altpocket` 形式）を更新する
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 3.1, 3.3, 4.1_

- [x] 4. テストと後方互換性検証を行う
- [x] 4.1 (P) アイテム部分更新 API のテストを追加する
  - データ層メソッド: タイトル+タグ同時更新、タイトルのみ、タグのみ、非所有者拒否のケースをテストする
  - ハンドラー: 空タイトルの 400 エラー、トリム処理、正常更新のレスポンスを検証する
  - _Requirements: 2.1, 2.3, 2.4, 3.2_

- [x] 4.2 既存タグ更新エンドポイントの後方互換性を検証する
  - PUT /v1/items/{id}/tags が従来どおりタグのみ更新できることを確認する
  - 既存の拡張機能契約テストが引き続きパスすることを確認する
  - _Requirements: 2.2_
